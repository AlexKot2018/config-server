
# Config Server

Инфраструктурный микросервис на базе **Spring Cloud Config Server**, выполняющий роль централизованного хранилища конфигураций для всех сервисов экосистемы. Позволяет управлять настройками приложений во внешнем Git-репозитории, обеспечивая динамическое обновление параметров без необходимости пересборки и перезапуска сервисов.

## 🛠 Технологический стек
* **Язык / Платформа:** Java 17 / Maven
* **Фреймворк:** Spring Boot 4.0.6
* **Компоненты Spring Cloud:** Spring Cloud Config Server (версия 2025.1.1)
* **Хранилище конфигураций:** Внешний Git-репозиторий (GitHub)

## 🏗 Архитектурная роль проекта
В распределенной системе `config-server` является фундаментом инфраструктуры и запускается самым первым:
1. При старте `config-server` клонирует приватный/публичный репозиторий с конфигурационными `.yml` или `.properties` файлами во внутренний кеш.
2. Другие микросервисы экосистемы (`api-gateway`, `user-service`, `notification-service`) на этапе предзапуска (`bootstrap`) обращаются к данному серверу по адресу `http://localhost:8888` за своими профильными настройками (параметры подключения к PostgreSQL, брокеру Kafka, SMTP-серверу и т.д.).

## ⚙️ Конфигурация и безопасность (application.yml)
Конфигурация сервера определяет порт по умолчанию (`8888`) и параметры интеграции с Git-репозиторием:

```yaml
server:
  port: 8888

spring:
  application:
    name: config-server
  cloud:
    config:
      server:
        git:
          uri: https://github.com
          default-label: main
          username: AlexKot2018
          password: \${CONFIG_GIT_TOKEN}
```

### 🔒 Обеспечение безопасности учетных данных:
В проекте строго соблюдается паттерн **Externalized Configuration** (вынесение секретов из кодовой базы):
* Чувствительные данные (GitHub Personal Access Token) не зашиты в коде, а считываются из переменной окружения `${CONFIG_GIT_TOKEN}`. Это исключает утечку приватных ключей и токенов авторизации при публикации репозитория в открытый доступ.

## 🧪 Тестирование
В проекте реализован базовый тест инициализации контекста:
* `ConfigServerApplicationTests.contextLoads()` — выполняет верификацию сборки и проверку корректности поднятия Spring-контекста с активным сервером конфигураций.

## 🚀 Сборка и локальный запуск
Для работы с проектом используется встроенный инструмент Maven Wrapper. перед запуском убедитесь, что в вашей операционной системе или файле `.env` задана переменная окружения `CONFIG_GIT_TOKEN`.

```bash
# Компиляция и сборка исходного кода
./mvnw clean compile

# Прогон тестов общего контекста
./mvnw test

# Запуск сервера конфигураций
./mvnw spring-boot:run
```

После успешного старта сервер доступен по адресу `http://localhost:8888/`. Проверить отдачу конфигурации для конкретного сервиса и профиля можно через HTTP-запрос, например: `GET http://localhost:8888/user-service/default`.
