# API Gateway

Инфраструктурный реактивный шлюз на базе **Spring Cloud Gateway**, выступающий единой точкой входа (Single Entry Point) для всей микросервисной экосистемы. Шлюз обеспечивает динамическую маршрутизацию запросов, балансировку нагрузки на инстансы сервисов и отказоустойчивость всей системы с помощью паттерна Circuit Breaker.

## 🛠 Технологический стек
* **Язык / Платформа:** Java 17 / Maven
* **Фреймворк:** Spring Boot 3.3.5 (Реактивный стек Project Reactor / WebFlux под капотом)
* **Компоненты Spring Cloud:** Spring Cloud Gateway, Config Client, Bootstrap, Netflix Eureka Client, Spring Cloud LoadBalancer (версия 2023.0.3)
* **Отказоустойчивость (Fault Tolerance):** Resilience4j (Реактивный предохранитель + Time Limiter)

## 🏗 Ключевой функционал и архитектурные решения

* **Реактивная маршрутизация и Service Discovery:** Шлюз интегрирован с сервером регистрации Eureka. Вместо жесткой привязки IP-адресов маршруты настраиваются динамически с использованием префикса балансировщика нагрузки `lb://` (например, `lb://user-service`), что позволяет автоматически распределять трафик между инстансами через `Spring Cloud LoadBalancer`.
* **Отказоустойчивость по паттерну Circuit Breaker (Resilience4j):** Внедрена защита от лавинообразного падения системы (Cascading Failures). Если один из целевых микросервисов начинает сбоить или отвечать с задержкой, предохранитель размыкает цепь, изолируя дефектный сервис.
* **Инициализация через Config Server:** Все настройки маршрутов (Predicates, Filters) и параметры предохранителя вынесены во внешний Config Server, адрес которого определяется на этапе предзапуска в `bootstrap.yml`.

## ⚙️ Конфигурация предохранителя (GatewayCircuitBreakerConfig)
В классе `GatewayCircuitBreakerConfig` настроена кастомная реактивная фабрика `ReactiveResilience4JCircuitBreakerFactory` со следующими политиками:
* **Размер скользящего окна:** 5 вызовов (sliding window для сбора статистики).
* **Порог отказов:** 50% (цепь размыкается, если половина запросов упали).
* **Таймаут ответа (Time Limiter):** 3 секунды (если сервис не ответил за 3 сек, вызов считается неудачным).
* **Время ожидания в открытом состоянии:** 10 секунд (период «охлаждения», во время которого запросы сразу перенаправляются на fallback, не нагружая упавший сервис).

## 🛡 Слой отказоустойчивых ответов (Fallback Layer)
Реализован специализированный `FallbackController`. При размыкании цепи или превышении таймаута шлюз перехватывает ошибку и мгновенно возвращает клиенту корректный, «красивый» дефолтный ответ (например, заглушку или кешированные данные), предотвращая падение клиентской части (фронтенда).

## 🚀 Сборка и локальный запуск
Приложение требует предварительно запущенных инфраструктурных сервисов: Config Server (на порту `:8888`) и Eureka Server.

```bash
# Компиляция проекта
mvn clean compile

# Запуск тестов на проверку инициализации контекста
mvn test

# Локальный запуск шлюза
mvn spring-boot:run
```
